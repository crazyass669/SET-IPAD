กลุ่ม A: XSS จาก external string ที่ยังไม่ escape (correctness/security, 4 จุด)
===============================================================================
บริบทร่วม: `it.note` (ค่าที่ /api/data-health ส่งกลับต่อ item) ถูก backend สร้างเป็น HTML string
โดยตรง แล้วฝั่ง frontend (loadDataHealth, dashboard.js) ใส่ผ่าน `${it.note || '—'}` ลง innerHTML
"แบบไม่ escape ทั้งก้อน" เพราะ note หลายจุดตั้งใจมี HTML tag (`<table>`/`<a onclick>`/`<div>`) ปน
อยู่ในสตริงเดียวกันโดยเจตนา (ใช้แสดงตารางย่อย/ลิงก์ในหน้า Data Health) — ต่างจาก
checkSetUniverseUpdates/checkMirrorUpdates (แก้ไปแล้วในรอบนี้) ที่ตัวมันเองสร้าง HTML ทั้งก้อน
ฝั่ง frontend ล้วนๆ เลย escape ตัวแปรภายนอกทั้งหมดในฟังก์ชันเดียวได้ตรงไปตรงมา — 4 จุดนี้ต้อง
escape เฉพาะ "ตัวแปรที่มาจากภายนอก" ในสตริงที่ปนกับ HTML literal ของเราเอง (ผสมกันในบรรทัด
เดียวกัน) ซึ่งเสี่ยง escape ผิดจุด/ลืมบางจุดมากกว่า ต้องทำทีละจุดอย่างระมัดระวังแทนที่จะ escape
รวดเดียวทั้งฟังก์ชัน

ความเสี่ยงจริง: ทั้ง 4 จุดต้องพึ่งข้อมูลจาก Wikipedia (index membership scrape)/SET.or.th (IPO
list) มีอักขระ HTML พิเศษ (`<`, `>`, `&`, `'`) ปนอยู่ในชื่อหุ้น/บริษัท ถึงจะ trigger ได้จริง —
ยังไม่เคยเจอเคสจริงในข้อมูลปัจจุบัน (ต่างจาก checkSetUniverseUpdates ที่มีจุดเสี่ยง onclick
attribute breakout ชัดเจนกว่า จึงแก้ก่อน) แต่หลักการเดียวกัน: แหล่งข้อมูลเป็น scrape จากเว็บ
ภายนอกที่ไม่ควบคุมได้ 100%
