------------------------------------------------------------------------
 โจทย์ตั้งต้น
------------------------------------------------------------------------
ผู้ใช้ถาม: พิมพ์แค่ชื่อหุ้น แล้วให้ระบบสร้างรายงานวิเคราะห์ครบ 10 หัวข้อ
ออกมาอัตโนมัติ ได้ไหม จากฐานข้อมูลที่มีอยู่ (financials.db, set_prices.db,
mirror cache US/HK/JP ฯลฯ)

10 หัวข้อที่ต้องการ:
  1. ธุรกิจคืออะไร — segment หลัก สัดส่วนรายได้ (%)
  2. ลูกค้าและ Switching Cost — กระจุกหรือกระจาย เปลี่ยนเจ้าง่ายไหม
  3. โมเดลรายได้ — recurring vs one-time, โตจาก volume/price
  4. งบการเงินล่าสุด — ตารางครบ: รายได้ กำไร Margin EPS FCF YoY%
  5. คุณภาพพื้นฐาน — ROE / ROIC / ROA / Margin trend
  6. Moat และจุดแข็ง — แบรนด์ / scale / switching cost / regulation
  7. Valuation — P/E, P/BV, EV/EBITDA เทียบ peer
  8. Optionality — upside ที่ตลาดยังมองไม่เต็ม
  9. ความเสี่ยง — Low/Medium/High แต่ละด้าน
  10. ผู้บริหาร — track record, MD&A สอดคล้องตัวเลขไหม

------------------------------------------------------------------------
 ข้อสรุปสำคัญ: แบ่งเป็น 2 ชั้น ความสามารถต่างกันมาก
------------------------------------------------------------------------
ชั้นตัวเลข (ข้อ 4, 5, 7) — ทำ auto จาก DB ในเครื่องได้เต็มที่ แม่นยำ
deterministic ไม่ต้องพึ่งเน็ต

ชั้น qualitative (ข้อ 1, 2, 3, 6, 8, 9, 10) — ไม่มี structured data ใน DB
ต้องอ่าน/ค้นเว็บสด (56-1, 10-K, ข่าว, analyst report) ทุกครั้งที่รัน
ผลลัพธ์ไม่ deterministic ขึ้นกับว่าหาข้อมูลของหุ้นตัวนั้นเจอครบแค่ไหน

  - Optionality: CPALL ถือ ~75% ของ CPAXT ที่เทรด P/BV แค่ 0.52x — sum-of-parts

  - เจอ NP YoY +86.4% ใน 2025Q3 -> เป็น base effect (ปีก่อนมีรายการพิเศษ

Qualitative (ต้องเว็บ):

  - ข่าวสดมาก: Tim Cook ก้าวลงจาก CEO เมื่อ 1 ก.ย. 2026 (4 วันก่อนวันคุย)
    CEO ใหม่ John Ternus ยังไม่มี track record ให้ประเมิน
    -> พิสูจน์ว่าข้อ 10 (และ 8-9 บางส่วน) cache ไว้ล่วงหน้าไม่ได้เลย
       ต้องค้นสดทุกครั้ง TTL สั้นมาก

 Guard ที่ต้องมี ก่อนใช้งานจริง (เจอจริงจาก 2 ตัวอย่าง ไม่ใช่ทฤษฎี)
------------------------------------------------------------------------
[1] Base effect — YoY ผิดปกติ (>±50%) ต้องเช็คว่าปีก่อนมีรายการพิเศษไหม
    ก่อนสรุปว่า "โตแรง/หดแรง" จริง

[2] P/B ไร้ความหมายเมื่อ equity ต่ำผิดปกติ/ติดลบ (buyback หนัก เช่น AAPL,
    เริ่มเห็นใน NVDA ด้วย) — ต้องซ่อนหรือติดธงเตือน ห้ามเอาไปเทียบ peer ตรงๆ

[3] ROE ไร้ความหมายเงื่อนไขเดียวกับ [2] — สลับไปใช้ ROA/ROIC แทน

[4] IFRS16 lease liabilities ปนใน Total Debt — ธุรกิจเช่าร้านเยอะ (ค้าปลีก
    อย่าง CPALL) จะดู D/E สูงเกินจริงเมื่อเทียบธุรกิจที่ซื้อที่ดินเอง

[5] ปีบัญชีไม่ตรงกันเวลาเทียบ peer ข้ามประเทศ (Apple ปิด ก.ย., MSFT ปิด
    มิ.ย., หุ้นไทยปิด ธ.ค.) ต้องระบุ FY-end ของแต่ละตัวกำกับเสมอ

[6] TTM vs FY ต่างกันได้มาก ต้องระบุชัดว่าใช้ฐานไหน (AAPL P/E 42.9x แบบ FY
    vs 36.2x แบบ TTM ต่างกันเยอะ)

[7] กลุ่มธุรกิจที่สูตรมาตรฐานใช้ไม่ได้: ธนาคาร/ประกัน (ไม่มี GPM, EV/EBITDA
    ไร้ความหมาย), REIT (ต้องใช้ FFO ไม่ใช่ EPS), holding company (งบรวม
    บิดเบือน) — ต้อง detect จาก sector แล้วสลับชุด metric หรือขึ้น "n/a"

[8] ชื่อผู้บริหาร/ข้อมูลบุคคล ต้อง cross-check เสมอ — เว็บค้นครั้งแรกให้ชื่อ
    CEO CPALL ผิดคน (สลับกับ CEO ของบริษัทในเครือเดียวกัน)

เต็มรูปโดยไม่ต้องมาคุยกับ Claude ทีละตัว ต้องต่อ backend เข้ากับ

  รวมประมาณ $0.10-0.50 ต่อการดู 1 หุ้น 1 ครั้ง (ประมาณการคร่าวๆ) ต้องมี
  API key + billing แยกจาก Claude Code subscription ที่ใช้อยู่

ทางเลือกไม่ใช้ API เพิ่มเลย: ทำแค่ชั้นตัวเลขเป็นปุ่ม auto ในแดชบอร์ด
ส่วน qualitative ให้พิมพ์ชื่อหุ้นขอ Claude ช่วยทำทีละตัวในแชท (แบบที่ทำ
CPALL/AAPL ให้ดู) ไม่มีค่าใช้จ่ายเพิ่ม แต่ไม่ auto ต้องเรียกเอง
