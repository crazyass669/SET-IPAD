################################################################################
 ส่วนที่ 1 — ทำไมต้องสำรอง 3 ชั้น แยกกัน (ไม่ใช้วิธีเดียวกันหมด)
################################################################################

ข้อมูลแต่ละชนิด "กู้คืนได้ง่าย-ยาก" ไม่เท่ากัน เลยใช้กลยุทธ์ต่างกัน:

  โค้ด            → เขียนเองได้ใหม่ถ้าหาย (แต่เสียเวลา) → git คุมเวอร์ชันพอ
  ข้อมูลรายวัน     → ดึงจากแหล่งเดิมใหม่ได้เสมอ (SET.or.th/Yahoo/TradingView
                     มี API เปิดให้ดึงย้อนหลัง) → แค่กัน "หายระหว่างทาง" พอ
  financials.db   → ดึงจาก Finnomena "API ไม่เป็นทางการ" — ถ้าปิด/บล็อกเมื่อไหร่
                     ข้อมูลงบย้อนหลัง 16 ปีที่มีอยู่แล้ว "สร้างใหม่ไม่ได้อีกเลย"
  set_prices.db   → มีหุ้นเพิกถอน/ควบรวมที่ Yahoo/SET ไม่มีให้ดึงซ้ำแล้ว (แก้
                     survivorship bias ไปแล้วเมื่อ 2026-07-17) → หายแล้วหายเลย
  sec_filings.db  → ประวัติ insider/ผู้ถือหุ้นใหญ่สะสมมาเรื่อยๆ → หายแล้วหายเลย

  สรุป: 4 ไฟล์ในชั้นที่ 3 คือของที่ "ห้ามหาย" จริงๆ — เป็นเหตุผลที่ต้องมีสำเนา
  นอกเครื่อง (offsite) ไม่ใช่แค่ในเครื่องเดียว

################################################################################
 ส่วนที่ 3 — ชั้นที่ 3: ไฟล์สร้างใหม่ไม่ได้ (อัตโนมัติผ่าน Task Scheduler)
################################################################################

┌─ งานที่ตั้งไว้: Backup_Offsite_Weekly ─────────────────────────────────────
  ความถี่:    ทุกวันจันทร์+พฤหัส 23:00 + ตอน log on (ถ้าสำรองล่าสุดเกิน 3 วัน)
              (Task Scheduler ต้องเปิดเครื่อง+ล็อกอินอยู่ตอนนั้น)
  รันอะไร:    task_backup_offsite.bat
              → python backup_financials_offsite.py "C:\SET_Dashboard_backup" --min-age-days 3
  สำรองไฟล์:  financials.db (~700MB, บังคับต้องมี), set_prices.db (~330MB,
              บังคับต้องมี), sec_filings.db + delisted_log.json +
              us/hk/jp_prices.db (ข้ามเงียบๆ ถ้าไม่เจอ)
  ตั้งชื่อไฟล์: <ชื่อเดิม>_YYYYMMDD.<นามสกุล> เช่น financials_20260718.db
  เก็บกี่ชุด:  3 ชุดล่าสุดต่อไฟล์ — เก่ากว่านั้นลบทิ้งอัตโนมัติกันโฟลเดอร์บวม
  ปลายทาง:    C:\SET_Dashboard_backup — โฟลเดอร์ mirror ของ Google Drive for
              Desktop (สำเนาในเครื่อง C: + sync ขึ้น Google Drive ใต้ "Computers")
              ย้ายมาจาก OneDrive เมื่อ 2026-09-04 เพราะพื้นที่ OneDrive เต็ม
  staging:    สคริปต์เขียนไฟล์ลง %TEMP% ในเครื่องก่อน แล้ว move ไปปลายทาง (กัน
              DriveFS เห็นไฟล์ .db ที่เขียนยังไม่เสร็จ) — ปิดด้วย --no-stage ได้
  บันทึกผล:   ผ่าน core/run_log.py → หน้า Data Health เห็นว่าสำรองล่าสุดเมื่อไหร่
              (เตือนเหลือง 35 วัน / แดง 60 วัน ถ้าไม่มีรอบไหนสำเร็จเลย)
  log ไฟล์:   logs\task_backup_offsite.log

┌─ ถ้าอยากรันสำรองเองตอนนี้เลย (ไม่ต้องรอวันจันทร์) ──────────────────────────
  ดับเบิลคลิก backup_financials_offsite.bat แล้วพิมพ์ path ปลายทางตอนถาม
  หรือรันคำสั่ง:
      python backup_financials_offsite.py "C:\SET_Dashboard_backup"

 ส่วนที่ 5 — วิธีเช็คว่าทุกอย่างยังทำงานอยู่ (ไม่ต้องมานั่งจำวันที่เอง)
################################################################################

┌─ วิธีที่ 1: หน้า Data Health ในแอป (แนะนำ — เช็คง่ายสุด) ────────────────────
  เปิดแอป → เมนู "🩺 Data Health" → เห็นทุกแหล่งข้อมูล + วันอัพเดทล่าสุด แบ่ง
  เขียว/เหลือง/แดง มี badge แดงเตือนบน nav bar อัตโนมัติถ้ามีอะไรค้างเกินเกณฑ์
  รวมการ์ด "สำรอง financials.db นอกเครื่อง" (เตือนเหลือง 35 วัน / แดง 60 วัน)

┌─ วิธีที่ 2: Windows Task Scheduler โดยตรง ───────────────────────────────────
  เปิด Task Scheduler → Task Scheduler Library → SET_Dashboard (โฟลเดอร์ย่อย)
  เห็น 3 งาน: Backup_Offsite_Weekly, Mirror_Quarterly, UpdateFinancials_Quarterly
  คลิกแต่ละงาน → แท็บ "General"/"Triggers" ดู "Next Run Time" ต้องเป็นวันที่
  ในอนาคตเสมอ (ถ้าเป็นอดีต/ว่างเปล่า = งานพัง ต้องแก้)
  หรือรันคำสั่งเช็คเร็ว:
      schtasks /query /tn "\SET_Dashboard\Backup_Offsite_Weekly" /fo list /v

┌─ วิธีที่ 3: เช็คไฟล์ log ตรงๆ ────────────────────────────────────────────────
  logs\task_backup_offsite.log, logs\task_mirror_quarterly.log,
  logs\task_update_financials_quarterly.log — เปิดดูรอบล่าสุดว่ามี error ไหม

┌─ ข้อควรระวัง: Task Scheduler ต้อง "เครื่องเปิด+ล็อกอินอยู่" ตอนถึงเวลา ──────
  task ตั้งเป็น "Run only when user is logged on" (ไม่เก็บรหัสผ่าน ปลอดภัยกว่า)
  ถ้าปิดเครื่อง/ไม่ได้ล็อกอินตอนนั้นพอดี งานจะ "ข้ามรอบไปเงียบๆ" ไม่ error ให้เห็น
  — Data Health จะเป็นตัวจับได้ว่าค้างนานผิดปกติ ไม่ใช่ Task Scheduler เอง


################################################################################
 ส่วนที่ 6 — วิธีกู้คืนข้อมูล (Restore) แต่ละสถานการณ์
################################################################################

┌─ กรณี A: ย้ายไปเครื่องใหม่ทั้งหมด ────────────────────────────────────────────
  ดู "ไฟล์ที่ต้องก็อปไปด้วย.txt" (มีอยู่แล้วในโฟลเดอร์ราก) — ระบุครบว่าไฟล์
  ไหนจำเป็น/ไฟล์ไหนข้ามได้ + ขั้นตอนติดตั้งเครื่องใหม่ทีละสเต็ป

┌─ กรณี B: financials.db / set_prices.db เสียหาย หรือหายจากเครื่องนี้ ─────────
  1. เปิด C:\SET_Dashboard_backup (หรือดาวน์โหลดจากเว็บ Google Drive > Computers)
  2. เลือกไฟล์วันที่ล่าสุด เช่น financials_20260718.db
  3. คัดลอกกลับมาที่โฟลเดอร์โปรเจกต์ แล้วเปลี่ยนชื่อกลับเป็น financials.db
     (หรือ set_prices.db ตามไฟล์ที่หาย)
  4. รีสตาร์ท server (ปุ่ม Restart ในแอป หรือปิดเปิด start.bat ใหม่)
  ** จะได้ข้อมูลถึงวันที่สำรองล่าสุดเท่านั้น (สูงสุดเก่ากว่าปัจจุบันไม่เกิน 7 วัน
     ถ้า Task Scheduler รันตรงตามกำหนดทุกอาทิตย์)

┌─ กรณี C: ข้อมูลรายวัน (set_data.json ฯลฯ) เสียหาย ────────────────────────────
  ไม่ต้องกู้จาก backup เลย — กด "Full Refresh" ในแอป ดึงใหม่จากแหล่งจริงได้เสมอ
  (หรือถ้าอยากได้ข้อมูล ณ วันที่เก่ากว่านั้นเป๊ะๆ ดึงจาก git history:
      git log --oneline -- set_data.json
      git checkout <commit-hash> -- set_data.json )

┌─ กรณี D: ฮาร์ดดิสก์/เครื่องพังทั้งลูก (worst case) ───────────────────────────
  1. โค้ด → git clone https://github.com/crazyass669/SET-IPAD.git บนเครื่องใหม่
  2. financials.db/set_prices.db/sec_filings.db/delisted_log.json → ดาวน์โหลดจาก
     Google Drive (เว็บ drive.google.com > Computers > เครื่องนี้ > SET_Dashboard_backup
     — หรือลง Google Drive for Desktop บนเครื่องใหม่แล้วเปิดจากโฟลเดอร์ mirror)
  3. ข้อมูลรายวัน → กด Full Refresh ครั้งแรก (~1-2 ชม.)
  4. ตั้ง Task Scheduler ใหม่ 3 งาน (ดู ส่วนที่ 4) — ไม่ได้ตามมาโดยอัตโนมัติ
     เพราะ Task Scheduler เป็นการตั้งค่าระดับ Windows ไม่ใช่ไฟล์ในโปรเจกต์
