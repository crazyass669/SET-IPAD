ที่มา: สำรวจ SET internal API รอบใหม่ (ดึง JS bundle ของ set.or.th มา grep หา
endpoint แล้วยิงทดสอบจริงด้วย bootstrap cookie ตาม pattern เดิมใน
sources/set_api.py) เจอ endpoint ที่ยังไม่ได้ใช้หลายตัว — แผนนี้เอาเข้า
"เมนูที่มีอยู่แล้ว" ทั้งหมด ไม่สร้างเมนูใหม่แม้แต่อันเดียว

กติกาที่ต้องยึดทุกงานในแผนนี้:
- ทุก endpoint ใช้ _bootstrap_headers() + _get_json() จาก sources/set_api.py
  ที่มีอยู่แล้ว ห้ามเขียน urllib/cookie เองซ้ำ
- ทุกฟังก์ชัน fetch ต้องมี validation gate + raise ให้ caller fallback
  (ตาม docstring หัวไฟล์ set_api.py — ห้ามรับข้อมูลไม่ครบเข้า pipeline เงียบๆ)
- frontend เรียก endpoint ใหม่ที่มี fallback ดึงสด ต้องใช้ _fetchTimeout()
  ไม่ใช่ fetch() เปล่า (ดู memory: frontend-fetch-timeout-pattern)
- ต้องบั๊ก ?v= ของ dashboard.js/.css ทุกครั้งที่แก้ (ตอนนี้ css=20260822,
  js=20260823) ไม่งั้น iPad แคชของเก่าค้าง
- หน้า static (GitHub Pages) ต้อง degrade สวยๆ เมื่อไม่มี local backend
- ทุกฟีเจอร์ต้องมีครบ 3 ชั้นคำอธิบาย (ดูหัวข้อ "มาตรฐาน UI" ด้านล่าง)

ทุกฟีเจอร์ที่เพิ่ม ต้องมีครบ "3 ชั้น" ไม่มีข้อยกเว้น:

1. tooltip (ชั้นเร็วสุด — hover เห็นทันที)
   - ปุ่ม/แท็บ/nav ใช้ title="..." ธรรมดา
   - ตัวเลขในการ์ดที่ต้องอธิบายยาว ใช้ data-vtip="..." (popup HTML ลอย
     — ดู _vtip/.val-tip ใน dashboard.js:25847 ที่หน้า Valuation ใช้อยู่)

2. tip box (ชั้นลึก — กด ℹ/? แล้วกางกล่องอธิบายเต็ม)
   - ใช้ pattern เดิมเป๊ะๆ:
     <span class="scr-tip-icon" onclick="_tipIconToggle(this,event)">ℹ
       <div class="scr-tip-box" style="width:270px">...</div></span>
   - onclick="_tipIconToggle" จำเป็นเสมอ — จอสัมผัส (iPad) ไม่มี hover
     ถ้าลืมใส่ ผู้ใช้ iPad จะเปิดกล่องไม่ได้เลย
   - หัวข้อหนาขึ้นต้น + <hr> คั่น + <span style="color:var(--text2)">
     สำหรับคำเตือน/ข้อจำกัด (ตามที่ FS_FILTERS ทำอยู่)
   - ทุกคอลัมน์ตารางใหม่ต้องมี tip อธิบายว่าเลขนี้คืออะไร + เกณฑ์สี

3. helper text (ชั้นบริบท — อ่านได้โดยไม่ต้องกดอะไร)
   - .page-sub ใต้ชื่อหน้า/การ์ด บอกว่าข้อมูลมาจากไหน สดแค่ไหน
   - บรรทัดเล็ก 11px สี var(--text2) ใต้ input/ตาราง บอกข้อจำกัด
   - **ทุกที่ที่ข้อมูลมีไม่ครบทั้งกระดาน ต้องเขียน coverage ให้เห็น**
     (เช่น ESG มีแค่ 38% — ห้ามปล่อยให้ผู้ใช้เดาเองว่าทำไมหุ้นหาย)

กฎเพิ่มสำหรับแผนนี้: ข้อมูลชุดใหม่ทุกตัวต้องบอก "ณ วันที่" ให้เห็น
(bookCloseDate ของ free float, foreignLimitAsOf ของ foreign room, asOf ของ
ESG) เพราะเป็นข้อมูลที่ไม่ได้สดรายวันทั้งหมด — ผู้ใช้ต้องรู้ว่ากำลังดูของ
เมื่อไหร่ ไม่ใช่คิดว่าเป็นค่าวันนี้

================================================================================
endpoint : /api/set/esg/list  ★ BULK 1 call ได้ 358 บริษัท
คุ้มค่า   : ★★★★☆  (ต้นทุนต่ำสุดในแผน แต่ coverage แค่ 38%)

⚠ ข้อจำกัดที่ต้องออกแบบรอบ (วัดจริงแล้ว):
  - มีข้อมูลแค่ 358/931 = 38% ของกระดาน
  - cgScore เบ้หนักมาก: score 5 = 285 ตัว, 4 = 40, 3 = 12
    → cgScore แทบแยกหุ้นไม่ออก (85% ได้เต็ม) ใช้เป็น "ตัวกรองออก" ได้

  - setesgRating กระจายดีกว่า: AAA 101 / AA 79 / A 67 / BBB 16 / ไม่มี 95
    → ตัวนี้ใช้จัดอันดับได้จริง

  → **กฎออกแบบ**: filter ทั้งกลุ่มนี้ต้อง "ไม่มีค่า = ไม่กรองทิ้ง" เป็น
    ค่าเริ่มต้นไม่ได้ (เพราะจะเงียบๆ ตัดหุ้น 62% ทิ้ง) ต้องมี checkbox
    "รวมหุ้นที่ไม่มีข้อมูล ESG ด้วย" ติ๊กไว้เป็น default + helper text
    บอก coverage ตรงๆ
