- งบการเงิน HK พร้อมอยู่แล้ว: mirror Finnomena (financials.db, namespace
  FINN:HK:{รหัส}) ครอบคลุม 105/105 ตัว (HSI 85 + HSTECH 30 + HSCEI 50,
  unique) = 100% มีรายการ, 103/105 มีงบจริง (2 ตัวเป็น empty marker:
  316=SJM Holdings, 868=Xinyi Glass — fallback Yahoo ตรงได้)
  -> งานนี้จึงเหลือแค่ "ราคา OHLC + technical (RS/EMA/Stage/RRG)"
     ไม่ต้องแตะงบการเงินเลย

- แหล่งรายชื่อ constituents (ตรวจ Wikipedia จริงแล้ว, ยืนยัน format):
  * HSI    (en.wikipedia, title=Hang_Seng_Index)
           table id="constituents", คอลัมน์ Ticker|Name|Sub-index
           ticker = {{SEHK|เลข}} เช่น {{SEHK|5}} -> normalize "0005.HK"
           Sub-index (Finance/Utilities/Properties/Commerce & Industry)
           ใช้แทน sector ได้เลย · ทดสอบดึงได้ 85 ตัว
  * HSCEI  (en.wikipedia, title=Hang_Seng_China_Enterprises_Index)
           table "ไม่มี id" -> regex หา header "Weighting...Industry" แทน
           คอลัมน์ Ticker|Name|Weighting(%)|Industry (ละเอียดกว่า HSI)
           ทดสอบดึงได้ 50 ตัว
  * HSTECH (zh.wikipedia, title=恒生科技指数 — ไม่มีหน้า en.wikipedia แยก)
           ไม่ใช่ wikitable — bullet list ใต้ {{Col-begin}}/{{Col-3}}
           รูปแบบ "*รหัส5หลัก [[ชื่อจีน]]" -> regex ^\*(\d{4,5})\s+\[\[
           ไม่ต้องแปลชื่อจีน (ใช้ name_map fallback เหมือน US) ทดสอบได้ 30 ตัว
  * ตรวจ TradingView components page แล้ว (2026-07-18) — ใช้ไม่ได้ ปิด
    paywall เห็นแค่ top 10/list ไม่ครบถ้า ไม่ login -> ตัดออก ใช้ Wikipedia
    เป็นแหล่งหลักตามเดิม (ยืนยันแล้วว่าตรงกับ mirror Finnomena 100%)

- normalize ticker ทุกดัชนี: f"{int(code):04d}.HK" (เช่น 20 -> "0020.HK",
  9988 -> "9988.HK") ให้ตรง yfinance

 PHASE 1 — โครงข้อมูลราคา (data infra)
========================================================================
[1.1] sources/hk_index_membership.py (ใหม่)
      - _fetch_wikitext(title, lang='en') รองรับทั้ง en/zh.wikipedia
        (เลียนแบบ us_index_membership.py._fetch_wikitext แต่เพิ่ม param lang)
      - parse_hsi(txt)   -> regex ตาราง id="constituents", ticker={{SEHK|N}}
      - parse_hscei(txt) -> regex หา header Weighting/Industry (ไม่มี id)
      - parse_hstech(txt)-> regex bullet list "*(\d{4,5})\s+\[\["
      - fetch_live_membership() -> คืน {HSI:[...], HSCEI:[...], HSTECH:[...],
        HSI_sector:{...}, HSCEI_sector:{...}} (HSTECH ไม่มี sector จาก
        Wikipedia -> ปล่อย Unknown, ใช้ ind จาก dr_universe.py เติมทีหลัง)
      - load_local()/save_local()/sync_membership() แนวเดียวกับ US
        -> data/hk_index_membership.json
      - validation กันหน้า Wikipedia เปลี่ยนโครง: raise ถ้า parse ได้
        < 20 ตัว (เทียบ known count 85/50/30)

[1.2] core/hk_store.py (ใหม่)
      - ก็อปโครงจาก core/us_store.py ทั้งฟังก์ชัน (DB_FILE = "hk_prices.db"
        แยกไฟล์ กันชนกับ set_prices.db/us_prices.db)
      - รวม iter_all_series()/iter_recent_series() ตั้งแต่วันแรก (ให้
        /api/hk-breadth ใช้ compute_breadth(store=hk_store) ได้ทันที
        แบบเดียวกับที่เพิ่งต่อยอด services/breadth.py ให้ US)

[1.3] backfill_hk_index_prices.py (ใหม่)
      - สคริปต์ดึงราคาย้อนหลัง max ครั้งแรก (เลียนแบบ
        backfill_us_index_prices.py) ใช้ sources/yahoo.py.fetch_all_batch()
        ตัวเดียวกับ US (รองรับ ticker .HK อยู่แล้ว — DR ใช้ fetch แบบนี้
        กับหุ้น HK มานานแล้วผ่าน dr_universe.py)
      - ticker list = union(HSI, HSCEI, HSTECH) จาก
        hk_index_membership.load_local() -> ~105 ตัว
      - เขียนลง hk_prices.db ผ่าน hk_store.upsert_bars()

      *** เช็คก่อนรันจริง: เวลาเทรด Asia/Hong_Kong ต่างจาก US/ไทย —
          ดู timezone dict ที่มีอยู่แล้วใน dr_universe.py:11 ว่าพอสำหรับ
          gap-update cutoff หรือไม่ (ไม่ใช่ blocker ของ full refresh
          รอบแรกที่ดึง max ทีเดียว) ***

========================================================================
 ข้อควรระวังเฉพาะ HK (สะสมจากการสำรวจ)
========================================================================
1. Ticker ทับซ้อนข้ามดัชนี (เช่น 700/9988/1211 อยู่ทั้ง HSI+HSTECH+HSCEI)
   -> ต้อง dedupe ก่อนดึงราคา (union ticker set ครั้งเดียว) แต่ metrics
      row เก็บ flag in_hsi/in_hstech/in_hscei แยกกันได้ตามจริง (ไม่ผูกขาด
      ดัชนีเดียวเหมือน US ที่ปกติหุ้นอยู่ดัชนีเดียวเป็นหลัก)
2. Timezone Asia/Hong_Kong ต่างจากทั้ง US (America/New_York) และไทย
   (Asia/Bangkok) — gap-update cutoff logic ต้องเช็คแยก ไม่ reuse cutoff
   ของ US ตรงๆ
3. HSTECH ไม่มี sector จาก Wikipedia (มีแต่ ticker+ชื่อจีน) — sector จะ
   โชว์ "Unknown" เว้นแต่ทับซ้อนกับ HSI/HSCEI ที่มี sector หรือทับซ้อนกับ
   dr_universe.py (ind field, ครอบคลุมบางส่วน)
4. TradingView link บนโมดัลกราฟ ต้องปรับ format เป็น HKEX:รหัส (ไม่ใช่
   SET:รหัส หรือ NASDAQ:รหัส แบบ US) — เช็ค _usTvLink()/tvLink() ที่มีอยู่
   ว่ารองรับ param exchange ได้เลยหรือต้องเพิ่มฟังก์ชันแยก _hkTvLink()
5. 2 ตัวที่งบเป็น empty marker (316, 868) — ไม่กระทบ Phase 1-4 (เป็นเรื่อง
   งบการเงินซึ่งพร้อมอยู่แล้วนอกเหนือแผนนี้) แค่บันทึกไว้เผื่อทำ Screener+
   HK ต่อในอนาคต
